# 占位符保护

游戏内的文本不是随便翻的：`%s` 少一个、颜色码掉一个、格式化参数顺序错了，游戏就会报 `MissingFormatArgumentException` 或者显示成乱码。mctrans 的做法是：**翻译前把占位符换成唯一标记，翻译后换回来并校验，对不上就不用这条译文**。

## 保护哪些东西

| ID | 类别 | 例子 | 默认正则 |
|---|---|---|---|
| P1 | MC 原版颜色码 | `§6`、`§l`、`§r` | `§[0-9a-fk-orx]`（忽略大小写） |
| P2 | MC 十六进制颜色 | `§x§7§f§0§0§0§0` | 由 P1 逐段覆盖（`§x` 也在字符类里） |
| P3 | Bukkit 颜色码 | `&6`、`&l` | `&[0-9a-fk-orx]`（`amp_codes` 可关） |
| P4 | printf | `%s`、`%1$d`、`%.2f`、`%%` | `%(\d+\$)?[-#+ 0,(]*\d*(\.\d+)?[sdifgeEuoxXcn%]` |
| P5 | MessageFormat | `{0}`、`{1,number}` | `\{\d+(?:,[^{}]*)?\}` |
| P6 | 转义序列 | `\n`、`\t`、`\r`、`\\`、`\"` | `\\[nrt\\"']` |
| P7 | 内联标签与实体 | `<br>`、`</b>`、`&amp;`、`&#65;` | `</?[A-Za-z][^>]*>\|&[A-Za-z]+;\|&#\d+;` |
| P8 | 自定义 | `#\[quest\]#` | `placeholder.custom_patterns` |

匹配是**按优先级从左往右**扫的，所以 `&amp;` 会整体作为 HTML 实体被保护，不会被当成 `&a` + `mp;`；`&6` 与 `&amp;` 同时存在时互不干扰。

`%%` 也算占位符：它是 printf 的转义写法，原样带回原文。

## 流程

```
原文: "&6Cost: %1$s gold"
  ↓ 掩码
送译: "⟦0⟧Cost: ⟦1⟧ gold"
  ↓ 渠道返回
译文: "⟦0⟧花费：⟦1⟧ 黄金"
  ↓ 还原 + 校验
结果: "&6花费：%1$s 黄金"
```

### 掩码

- 每处占位符按出现顺序编号，替换成 `sentinel` 模板渲染出的唯一标记（默认 `⟦0⟧`、`⟦1⟧`…）
- 掩码只作用于送译的字符串；文件的键、结构、注释从来不经过渠道
- 掩码后的文本与注册表成对传递，注册表记录每处占位符的原始内容

### 校验（三条，缺一不可）

1. **掩码完备性**：每个标记在译文中必须出现且只出现一次；不允许出现未知的标记（说明模型编了一个）
2. **多重集一致**：还原后重新扫描占位符，与原文比对。原文没有的占位符不允许出现在译文里（`strict_new = true` 时）
3. **首尾空白**：译文若丢了原文的首尾空白，按原文补齐

任何一条不满足 → **丢弃这条译文，保留原文**，并在报告里记一条 `placeholder_failures`，包含文件、单元、原文摘要和原因。

### 为什么要第 2 条

模型有时会「顺手」把 `%s` 改成 `%d`、把 `§6` 删掉，或者在译文里加一个原文没有的 `%s`。这类译文即使能写进文件，游戏里也会炸或显示异常，所以宁可保留原文。

如果译文只是把标记挪了位置（比如 `⟦0⟧⟦1⟧` 变成 `⟦1⟧⟦0⟧`），当前实现会认为数量一致而放行——但带序号的参数（`%1$s`、`{0}`）顺序变了是有风险的，遇到这种情况请在报告里人工抽查。

## 自定义

```toml
[placeholder]
sentinel = "⟦{}⟧"          # 掩码模板
amp_codes = true           # 是否保护 &6 风格
strict_new = true          # 译文引入新占位符是否拒绝
custom_patterns = [
  "#\\[quest\\]#",         # 自定义正则（Rust regex 语法）
  "%\\{[^}]+\\}",           # 再比如 %{...} 这种写法
]
```

改 `sentinel` 时注意：有些模型对生僻符号的处理不稳定，`@@0@@` 这类纯 ASCII 通常更稳；如果发现译文里的标记被改写或丢失，换个 sentinel 再试。

## 术语表与占位符的交互

术语后处理只替换**占位符之外**的片段：文本先按占位符切开，逐段做术语替换，再拼回去。所以术语里就算含 `%`、`§` 也不会误伤。

送译时术语表也会注入 system prompt（取前 30 条），让模型直接用你的译法。

## 已知边界

- 只保护**单条文本内部**的占位符；如果原文把参数拆到了两个相邻条目里（少见），工具看不出来
- 文本组件（`{"text":"…"}`）只保护 `text` 字段里的占位符，`hoverEvent`、`clickEvent` 等字段整块不动
- `§x` 十六进制颜色是逐段保护的（`§x`、`§7`、`§f`…），如果某个模型把 `§x` 单独吃掉，校验会发现标记数量不符并保留原文
